# MARA Terminal — Task 6.1: Deploy Backend Fixes and Restore Market Data

## Objective
Resolve the degraded backend and unavailable market overview in production. Deploy the two locally identified fixes, verify cache connectivity, restore real provider-backed market data, and validate the refresh workflow.

## Current production evidence
- Dashboard URL returns HTTP 200, and the deployed frontend includes the Task 6 refresh interaction.
- `GET /api/health` returns HTTP 200 but reports `status: degraded` and `cache: fail`.
- `GET /api/markets/overview` returns HTTP 200 but reports `market_status: Unavailable`, empty categories, no prices, and missing `feed_health` and refresh timestamps.
- Two local backend fixes have been made:
  1. The health check passed incorrect arguments to the cache.
  2. Cold-cache overview responses omitted feed-health and timestamp fields.
- The backend test suite passes 29 tests locally. Neither fix is yet production-verified.

## Phase 1 — Review and deploy
1. Inspect the existing changes and confirm both fixes are correct.
2. Confirm all relevant backend tests pass, including the cold-cache overview and cache health tests.
3. Verify the deployment configuration, backend service, startup command, and deployment target.
4. Deploy the backend changes using the project's existing deployment workflow.
5. Confirm the deployed backend is running the new revision. Do not assume the frontend deployment updated the backend.
6. Never print secrets, API keys, cache URLs, or internal authentication tokens.

## Phase 2 — Diagnose cache failure
1. Request the deployed `/api/health` endpoint.
2. Determine the actual reason the cache reports failure: incorrect configuration, unreachable service, authentication, connection timeout, or another documented cause.
3. Check whether Redis is configured and reachable. If Redis is optional, verify the intended in-memory fallback works and report its limitations accurately.
4. Fix the underlying configuration or connectivity defect if authorized and within the project's existing architecture.
5. Do not report a healthy cache merely by suppressing exceptions or changing the health status.
6. Recheck health after deployment and report the actual cache mode and result.

## Phase 3 — Verify market overview
1. Request the deployed `/api/markets/overview` endpoint with a cold cache and again after a successful refresh.
2. Confirm the response always includes the expected `feed_health`, freshness/retrieval timestamps, market status, and category structure—even when data is unavailable.
3. Check each supported category independently: Indian indices, US benchmarks, forex, commodities, and digital assets.
4. Trace missing values through the provider request, normalization, cache, and response serialization layers.
5. Verify real provider responses and canonical symbols. Handle renamed, invalid, missing, or temporarily unavailable symbols individually so one failed symbol does not erase all categories.
6. Never fabricate prices or substitute mock data to make the dashboard appear populated.
7. Preserve truthful `DELAYED`, `STALE`, and `OFFLINE` classifications. Account for exchange hours and legitimate provider delays.

## Phase 4 — Test authenticated RELOAD
1. Identify the intended authentication mechanism and required production configuration without revealing secret values.
2. Test the refresh endpoint using the authorized mechanism.
3. Verify that an accepted request actually schedules and completes refresh work and that the overview reflects the resulting data or a truthful failure.
4. Verify repeated requests respect the cooldown and lock behavior.
5. Verify unauthorized requests are rejected and the internal refresh secret is never exposed to frontend code or public responses.
6. If production access or authentication is unavailable, report the exact blocked test and what access is required. Do not claim refresh is verified.

## Phase 5 — Final verification
Run the relevant backend tests, compile checks, frontend build, and available smoke tests. Check the deployed browser network requests, console, prices, category states, and timestamps.

Provide a final report with:
- Deployment revision and deployment result.
- Health endpoint status and cache diagnosis.
- Overview endpoint status and representative sanitized response fields.
- Results by market category, including provider and retrieval timestamps where available.
- Authenticated refresh, cooldown, and authorization test results.
- Any remaining failures, access limitations, and untested items.

Distinguish local verification from production verification. Do not claim that market data has been restored until real provider-backed data is confirmed in production. Do not modify unrelated features or delete task files.
