# MARA STOCK DASHBOARD — INDEX RESEARCH API FAILURE INVESTIGATION

## Objective
Investigate and resolve repeated HTTP 503 errors affecting the research and intelligence APIs when accessing the NASDAQ Composite index (`^IXIC`).

Production deployment:
https://mara-stock-terminal.vercel.app/#/markets

Affected symbol:
`^IXIC` — NASDAQ Composite Index

## 1. Observed Production Errors

The following endpoints consistently return HTTP 503:

- `/api/stocks/%5EIXIC/research`
- `/api/stocks/%5EIXIC/v4-intelligence`
- `/api/stocks/%5EIXIC/deep-research`
- `/api/stocks/%5EIXIC/macro-explorer`

The frontend retries each request, but the failures persist.

The frontend reports:
- Deep research notice for ^IXIC.
- Macro explorer fetch error.
- Research fetch non-fatal notice.
- Mara v4 intelligence notice.

These failures appear across four separate research services.

## 2. Primary Investigation — Index Symbol Compatibility

Investigate whether the backend correctly supports index symbols, particularly `^IXIC`.

Check:

1. URL encoding and decoding of caret-prefixed symbols.
2. Whether `%5EIXIC` is correctly decoded into `^IXIC`.
3. Whether the backend symbol validator accepts `^` characters.
4. Whether symbol normalization accidentally removes or modifies the caret.
5. Whether provider adapters correctly recognize index instruments.
6. Whether the data providers support NASDAQ Composite historical data, quotes, fundamentals, and macro-related information.
7. Whether index symbols are incorrectly processed using stock-specific logic.

Check similar instruments where applicable:
- `^IXIC` — NASDAQ Composite
- `^GSPC` — S&P 500
- `^DJI` — Dow Jones Industrial Average
- `^NSEI` — NIFTY 50

Do not assume every provider supports every index.

## 3. Investigate Shared Backend Dependencies

All four endpoints fail simultaneously.

Trace their dependency chains and investigate:

- Financial data provider availability.
- Provider-specific symbol support.
- Rate limits and HTTP 429 responses.
- Request timeouts.
- Cache failures.
- Database connectivity.
- Shared service exceptions.
- Backend worker timeouts.
- Render service restarts.
- Missing or invalid production environment variables.

Determine whether these endpoints share a failing provider, service, or infrastructure dependency.

## 4. Index-Aware Architecture

Review whether the current instrument architecture distinguishes between:

- Individual equities.
- Market indices.
- ETFs.
- Commodities.
- Currency pairs.

If index-specific handling is missing, implement it using the existing architecture and Core Contracts.

Requirements:

- Correctly normalize and preserve index symbols.
- Support provider-specific symbol mappings where necessary.
- Avoid treating indices as ordinary company stocks.
- Do not request company fundamentals or financial statements for indices.
- Provide index-appropriate market statistics and research.
- Handle unsupported data categories gracefully.
- Preserve compatibility with existing stock research functionality.

Do not introduce hardcoded special cases for only `^IXIC`.

`[MarketWS] Vercel detected - using polling fallback`

`[MarketWS] Starting polling fallback`

- Index research failures do not interrupt market overview or other workspaces.
- Research panels display meaningful error and unavailable-data states.
- Failed requests do not trigger unnecessary retry storms.

Do not modify working MarketStatus or MarketWS logic without identifying an actual defect.

## 6. Error Handling and Reliability

Implement appropriate behavior for:

- Unsupported instrument types.
- Unsupported provider capabilities.
- Temporary upstream outages.
- Rate limiting.
- Missing historical data.
- Partial research results.

Requirements:

- Use bounded retries with appropriate backoff.
- Preserve stale-cache fallback where available.
- Isolate optional research service failures.
- Return meaningful structured error responses.
- Do not return fake data.
- Do not convert all failures into HTTP 200.
- Do not silently suppress exceptions.

## Execution Instructions

Follow this sequence:

INVESTIGATE → TRACE DEPENDENCIES → IDENTIFY ROOT CAUSE → IMPLEMENT FIX → TEST → VERIFY.

Do not assume the caret character is the root cause merely because the affected instrument is an index.

Investigate the actual backend response and provider exception before changing symbol normalization or API routing.

Preserve the existing architecture and avoid unnecessary refactoring.

Do not claim production resolution until the deployed endpoints have been tested successfully.
